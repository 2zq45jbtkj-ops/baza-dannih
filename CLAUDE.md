# baza-dannih — контекст для Claude Code

## Проект

Отдельный проект от Telegram Mini App — см. `../Telegram Mini App - your_vocal/.../CLAUDE.md` для бота.

- **Prod URL:** `baza-dannih.vercel.app`
- **GitHub:** `git@github.com:2zq45jbtkj-ops/baza-dannih.git` (main)
- **Vercel project:** `prj_Jpv5XO4ATEW2xA6EJ4g8LUpysixZ`, team `team_bu9F0zOqL8isyjDABasvhj70`
- **Деплой:** push в main → Vercel автоматически собирает. Node 24.x (`package.json engines`).
- **Локальный дев-сервер:** `.claude/server.js` — раздаёт `index.html` с диска, проксирует `/api/*` на живой `baza-dannih.vercel.app` (т.е. локально всегда бьёт по продакшен-базе — осторожно с тестовыми действиями типа удаления).

## Доступ к сайту

Весь сайт закрыт паролем (`#site-lock` оверлей, `api/site-login.js`, env `SITE_PASSWORD`), 30-дневная сессия в localStorage (`bd_auth_ts`). Оверлей **не** показывается на `localhost`/дев-прокси и в Claude Code превью — только на проде (`baza-dannih.vercel.app`).

## Доступ к API (`api/_auth.js`)

Пароль закрывает страницу, но не ручки — поэтому у API своя проверка. Общий модуль `api/_auth.js` (файл с `_` — это не функция Vercel, слот из лимита 12 он не занимает, как `_db.js`/`_telegram.js`). Два уровня:

- **Преподаватель** — заголовок `X-Site-Auth`. Токен выдают `site-login.js` (по паролю сайта) и `admin-auth.js` (по двум админ-ключам — ими входит «Режим админа» в Mini App). Браузер держит его в localStorage (`bd_auth_token`), `apiGet`/`apiSend` в `index.html` цепляют его сами; на 401 показывается оверлей пароля.
- **Ученик** — заголовок `X-Player-Session`, 12 часов. Выдаёт `player-tracks?action=auth` в обмен на код (`students.telegram_token`). `studentId` берётся **из подписанного токена**, параметр `?studentId=` при этом игнорируется.

Токены — HMAC от `SITE_PASSWORD`, в базе не лежат (проверка не стоит запроса к Postgres). Смена пароля сайта разом отзывает все выданные токены. Если `SITE_PASSWORD` не задан — ручки отвечают 503, а не пускают всех (fail-closed).

Закрыты все ручки с данными учеников: `students.js`, `intake.js`, `dicts.js`, `warmups.js` — целиком; `lessons.js`, `player-tracks.js`, `player-upload.js` — с оговорками (ниже). Открыты по-прежнему: `student-public.js` и `recording.js` (там свои токены в URL), `health.js`, сами ручки входа.

Три места, где `requireTeacher` нельзя ставить «первой строчкой», — если переписываешь, проверь именно их:

- **`lessons.js`** — проверка стоит **после** ветки `?part=hw-reminder`. У крона своя защита по `CRON_SECRET`, и Vercel Cron шлёт `Authorization: Bearer`, а не `X-Site-Auth`: поднимешь `requireTeacher` выше — ежедневные напоминания о ДЗ молча перестанут рассылаться.
- **`player-upload.js`** — проверяется только тело `blob.generate-client-token`, и токен берётся из `clientPayload`, а не из заголовка: загрузку начинает `VercelBlob.upload()`, а у него в опциях заголовков нет вообще. Второй тип тела, `blob.upload-completed`, присылают серверы Vercel Blob — своего токена у них взяться неоткуда, закроешь целиком — коллбэк начнёт получать 401 (он защищён HMAC-подписью `x-vercel-signature`).
- **`warmups.js`** — проверка **после** обработки `OPTIONS`: preflight ходит без заголовков, и 401 на нём браузер покажет как «сервер недоступен», так и не отправив настоящий запрос. Ветка `?audio=` закрыта вместе со всем остальным.

В `index.html` четыре запроса идут мимо `apiGet`/`apiSend` и несут токен сами: `/api/lessons` в `ensureLessonCounts`, `/api/warmups?audio=`, и три `VercelBlob.upload()` через `clientPayload` (хелперы `apiAuthHeaders`/`apiUploadPayload`). Без токена остаются только сами ручки входа — `site-login` и `admin-auth`.

Локальная разработка: оверлея на `localhost` нет, поэтому токен в проксируемые запросы подставляет сам `.claude/server.js` — ему нужен прод-пароль: `SITE_PASSWORD='…' node .claude/server.js`. Без переменной закрытые ручки ответят 401, а список учеников и Репертуар будут пустыми (фронт глотает ошибку молча). Именно ради дев-прокси `player-upload.js` принимает токен и заголовком тоже: на localhost в localStorage его нет.

### Кто ещё ходит в эти ручки

В `/api/*` ходит не только `index.html`. Перед тем как закрывать любую ручку — проверить обоих, и **выкладывать их раньше базы**: клиент с токеном работает со старым API, а новый API без токена клиента не пустит.

| Проект | Где лежит | Что дёргает |
|---|---|---|
| Telegram Mini App | `~/Desktop/your_vocal-оферта` (git, remote `your_vocal`) | `students` (GET+DELETE, «Режим админа»), `admin-auth`, `student-public` |
| Плеер урока | `~/Desktop/Плеер для уроков Онлайн/urok-pleer` (без git) | `player-tracks` (`?action=auth` + GET списка) |

Ловушка: папка `~/Desktop/Telegram Mini App - your_vocal/` — **устаревшие снимки**, не исходник (там три разных `app.js`, все отстают от прода). Рабочая копия Mini App — `your_vocal-оферта`. Оба проекта деплоятся не из git, а CLI/MCP, так что «что на проде» надёжнее смотреть через Vercel, а не по диску.

## Структура данных

Postgres (Neon, подключено через Vercel Storage). Схема создаётся идемпотентно в `api/_db.js` → `ensureSchema()` (паттерн: `CREATE TABLE IF NOT EXISTS` + `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` в конце функции при каждом новом поле — **так добавляются все новые колонки**, отдельных миграционных файлов нет).

Таблицы: `students`, `student_intake` (вся анкета/Кабинет, одна строка на ученика, JSONB для структур/качеств/модов), `lesson_log` (Дневник занятий), `field_dicts` (общие словари для компонента Справочник), `player_tracks` (дистанционный плеер).

## API (`/api/*`)

- `students.js` — CRUD учеников, статус, телеграм-токен
- `intake.js` — GET/POST анкета ученика (весь Кабинет одним объектом, названные колонки — не free-form JSONB)
- `lessons.js` — Дневник занятий + ветка `?part=hw-reminder` (см. «Напоминания о ДЗ»)
- `dicts.js` — словари для Справочника (pinned/added варианты)
- `student-public.js` — публичный профиль по telegram-токену (дёргает Telegram Mini App)
- `admin-auth.js` — два 13-символьных ключа для админ-режима в Mini App (+ выдаёт токен преподавателя)
- `site-login.js` — пароль от всего сайта (+ выдаёт токен преподавателя)
- `player-tracks.js` — песни ученика, вкладка «Репертуар» и плеер урока; тут же вход ученика по коду (`?action=auth`)
- `player-upload.js` — разовый токен на загрузку аудио в Vercel Blob
- `health.js` — healthcheck
- `_db.js`, `_telegram.js`, `_auth.js` — общие модули, **не** функции (префикс `_`), в лимит 12 не входят

## Напоминания о домашнем задании

Раз в сутки бот пишет ученику, если **оба** условия верны: задание не отмечено выполненным и ученик сутки не открывал Mini App.

- Расписание — `vercel.json` (`0 15 * * *`, UTC). Крон бьёт в `/api/cron/hw-reminder`, оттуда rewrite на `/api/lessons?part=hw-reminder` — в `path` крона намеренно нет query-строки, а rewrite не создаёт новую функцию и не ест лимит 12.
- Ручка закрыта `CRON_SECRET` (env в Vercel): Vercel сам шлёт `Authorization: Bearer $CRON_SECRET`. Без переменной ручка отвечает 503 и ничего не рассылает.
- Колонки `students.last_seen_at` / `students.hw_reminder_sent_at`. Первую пишет Mini App при каждом запуске (`POST /api/student-public` телом `{seen:true}`), вторую — сам крон, и **только после успешной доставки**, чтобы заблокировавший бота ученик остался в очереди на завтра.
- Ученик отмечает задание выполненным в Mini App → `POST /api/student-public` с `{hwDone:{title,due,done}}` → статус внутри `lesson_log.hw_items` становится `выполнено учеником` (видно в Дневнике). Задания своего id не имеют — ищутся по паре `title+due`.
- Про задания без дедлайна и просроченные больше чем на 7 дней бот молчит — иначе напоминания идут бесконечно.

## Компонент «Справочник»

Общий переиспользуемый list-picker (единичный и множественный выбор) — используется ~34 раза по всему Кабинету. Капсулы-чипы в поповере, min-width 340px/max-width 480px (чтобы длинные варианты не обрезались), текст переносится, а не клипается. «+ Добавить свой вариант» пишет в `field_dicts`. Детали — `kbSpravochnikControl`/`kbSpravochnikSingleControl` в `index.html`.

## Дистанционный плеер

Треки ученика с раздельными дорожками вокал/инструментал (разделены заранее в приложении типа Moises, грузятся готовыми mp3/wav в Vercel Blob), синхронное воспроизведение + раздельная громкость.

Текущее состояние (проверено по git, не на глаз):
- Таблица `player_tracks` создаётся в `ensureSchema()`, `api/player-tracks.js` и `api/player-upload.js` закоммичены и задеплоены (`0b752a8`, `b8b9c40`). Отдельного `api/player-auth.js` нет и быть не должно — вход ученика живёт веткой `?action=auth` внутри `player-tracks.js`, чтобы не тратить слот из лимита 12.
- UI в `index.html` — вкладка «Репертуар» (`repWireCard` и соседние функции). Код входа ученика живёт **не там**, а в шапке карточки, строкой «Урок» рядом с «Telegram» (`wireRoomCode`, `roomCodeLoad`): во вкладке его не находили.
- Страница ученика — **отдельный проект** `urok-pleer` (`~/Desktop/Плеер для уроков Онлайн/urok-pleer`, без git, деплой через Vercel CLI/MCP, не пушем). Ходит с чужого домена в этот же эндпоинт, поэтому на нём `Access-Control-Allow-Origin: *`. **Задеплоен и работает** — `urok-pleer.vercel.app` отдаёт страницу «Плеер · занятия вокалом». Файл `СТАТУС.md` в той папке устарел.
- Таблица `lesson_rooms` читается: `?action=room` выдаёт/перевыпускает короткий код (6 символов, алфавит без 0/O/1/I/L — код диктуют голосом), `?action=auth` пускает по нему или по длинному `telegram_token`. Поле ввода в плеере ограничено шестью символами, то есть длинный токен туда руками не ввести — только короткий код.
- Ссылка для ученика: `urok-pleer.vercel.app#КОД`. В хвосте ждут **сам код и ничего больше** — плеер проверяет `location.hash` маской `/^[A-Z0-9]{4,40}$/`. Приставки вроде `#lesson=` эту маску не проходят и молча высаживают на экран ввода кода.
- Синхронной комнаты урока (общее воспроизведение у двух сторон) ещё нет. Комментарии про «это пишет приложение для онлайн-уроков» в `player-tracks.js` описывают задуманное.

## Дизайн-система

- Светлая тема: фон `#F2ECE7`, панели `#fff`, текст `#2E2A27`, акцент терракота `#AE5F3F`/`#8A3324`, линии `#E4E0DA`
- Тёмная тема (`body.dark`): фон `#1C1A18`, панели `#26221F`, текст `#EFE9E3`, линии `#3A342F`, муted `#9C9188` — переключается через CSS-переменные в `:root`/`body.dark`, но **точечные элементы с захардкоженными hex-цветами (не var()) регулярно всплывают как баги** — при добавлении нового UI всегда использовать `var(--bg)/--panel/--text/--line/--muted`, не хардкодить светлые hex
- Уровни A–D: терракота/синий/жёлтый/фиолетовый (`--lvlA..D`)
- Даты: нативные `<input type="date" lang="ru">` — без `lang="ru"` браузер показывает mm/dd/yyyy вместо дд.мм.гггг независимо от `<html lang="ru">`

## Повторяющиеся грабли

- Превью-скриншот в Claude Code иногда рендерит сплошной пустой кадр без видимой причины — DOM/computed-style проверка через `preview_eval` надёжнее, чем доверять одному скриншоту
- Клик, меняющий только часть state, может не затронуть DOM-узлы, которые рендерятся другой функцией (пример: `toggleMask()` менял `_maskActive`, но кнопка `#maskToggle` рендерится в `render()`, а не в `renderStudentList()` — пришлось патчить узел кнопки вручную)
- Новое поле в `intake`/`lesson_log` не сохранится, пока не добавлено (а) колонкой в `ensureSchema()` и (б) явно в SELECT/INSERT/UPDATE конкретного `api/*.js` — таблицы не JSONB-блобы с гибкой схемой
